# CLAUDE.md — VerEKOS

VerEKOS is EKOS's sibling with a proof spine. It states EKOS's promises (an
append-only ledger, evidence for every conclusion, read scope, conflicts kept,
human-only review, determinism) as theorems about a Lean model, and scores the
model against EKOS's own fixtures and tests with EKOS's own output as the
control. Read `README.md`, then `project/PLAN.md` (the root's running log of
lanes), then the design `docs/design/VEREKOS-DESIGN-2026-10-19.md`.

There is no Isabelle layer. It was dropped on 2026-10-19; every kernel is Lean
in `world/`. Older text that says Isabelle, HOL, SML or AFP is history.

## Rules every lane follows

- **Own one directory.** A lane writes only the paths its brief names. Read
  anything; edit nothing another live lane owns (PLAN lists who owns what).
- **Never write into `/Users/ember/dev/minidregg` or `/Users/ember/dev/EKOS`.**
  No edits, no in-tree builds (the minidregg pin is cloned under
  `world/.lake/packages`). Clones and scratch go under `var/`. The one
  exception on record: the EKOS release binary the fixture and slice-1 lanes
  use was built in EKOS's git-ignored `ekos/target/` on 2026-10-19; the next
  EKOS build sets `CARGO_TARGET_DIR=/Users/ember/dev/verekos/var/ekos-build/target`.
- **Commits:** named files only (`git add <path>`), never `git add -A`, never
  `git stash`, `git reset` or `git checkout -- <file>` on someone else's work.
  Unsigned commits are fine (`git -c commit.gpgsign=false commit`). Torn commits
  are fine. Commit and **push often** (`origin` is `emberian/verekos`, branch
  `dev`): `git pull --ff-only` then `git push`, after every harvest or
  verification. For a message with backticks, write it to a file and use `-F`.
- **Processes:** every detached job writes a PID file (`nohup … & echo $! >
  var/<lane>/job.pid`) and is stopped only by that PID. Never kill by pattern:
  no `pkill -f`, `pkill -x`, `killall`, `kill -u`.
- **Builds** run under `nice -n 10`, one at a time on this machine. On hbox use
  `swarm-build <cmd>`; hbox's disk is tight (about 30 GB free), so write only
  small run roots there and never build or copy trees.
- **Tests:** run the narrowest thing that could refute you (one drift record,
  one panel, one Lean file); never an unfiltered cargo suite.
- **Disk pressure:** stop writing, report, wait. Delete only what your own lane
  created.
- **Theorems:** no `sorry`, `admit`, new `axiom` or `native_decide`. Read the
  statement, not the name; a tautology or a hypothesis that assumes the
  conclusion is not progress. Say which hypotheses a theorem needs.
- **Untrusted by construction:** a parser, a fetch, a mapper guess, a model
  call. Say so in the output.
- **Numbers or nothing:** a report states its panel numbers or says it has
  none. A green build is not a number; a control scored against itself is not
  a measurement of a kernel.
- **Model mix:** GLM lanes are fine for breadth; intersperse Sonnet and Opus
  (and the root's own reading) so the project does not drift into a
  lower-intelligence basin. Grok lanes set a context cap (see PLAN).
- **Memos** go in `notes/<LANE>-<topic>.md`: a short summary first, what was
  built, the numbers, what could not be verified, follow-ups. The root records
  the lane's status in `project/PLAN.md`.
- **Plain words**, for a reader who is not a software engineer: what it does,
  what it proves, what it cannot do yet. Cite `path:line`.

## Panel conventions (target shape; the move list is lane C of `docs/design/explorations/05-next-lanes.md`)

A panel item is an input and nothing else. EKOS's answers go in
`controls/<panel>.control.jsonl`; what the transcribed Rust test asserts goes
in `controls/<panel>.expected.jsonl`; inputs in `panels/<family>/items.jsonl`;
the drift record in `panels/<family>/drift.json`, checked by
`panels/transcribed/drift_check.py`. New panels follow this shape; older ones
are listed as exceptions in `tools/scoreboard/README.md`.
