# VerEKOS Invariant Census — EKOS Core, as Candidate Theorems

**Summary.**
EKOS states ~12 invariants in prose (CLAUDE.md "Key invariants" + 7 RFCs) but enforces far more in code; this memo catalogues 42 as candidate theorems with their real Rust symbols, their current enforcement (named test, source-scan guard, or convention), and whether the code actually satisfies each as stated.
The strongest formalization targets are: the append-only/versioned ledger (`append_versioned`, `content_signature`, `object_at`, `object_history`), the read-scope decision (`Compiled::visible`, `ScopedStore`), the exact-name merge gate (`MergeProposal::exact_name_match`), the conflict detectors (`ekos_semantic::conflicts`), and the redaction baseline (`ekos_common::redaction`).
Four "documented" invariants are enforced only by convention (Runtime read-only, pass determinism, evidence-for-every-conclusion, secrets-never-stored) and three RFC 0007 statements have drifted from the code (threshold 0.85→0.90, `structural_score` now Jaccard, "all objects become candidates" now excludes registry-keyed kinds).
The human-only boundary is enforced by four separate string-containment source scans of `commands/mcp.rs` — robust to omission, not to aliasing.
Everything below was read from source at the cited `path:line`; what I could not verify is listed at the end.

Columns: **Name | Theorem (plain words, real symbols) | Enforced today by | Satisfied as stated? | Proof side conditions**

## Invariants the code enforces that no document states

1. **Retraction is append-only state change.** `fold_state` (`/Users/ember/dev/EKOS/ekos/crates/ledger/src/fact_ledger.rs:1676-1694`): a `FactOp::Retract` removes a slot from the *reconstructed* state while remaining an entry in history — i.e. "current state" and "log" are different objects with different persistence laws. No RFC states this pair; CLAUDE.md's "no tombstone exists" is about object-level delete and is true, but the fact layer has attribute-level retraction.
2. **Search-index self-heal on close.** `Drop for FactLedger` commits the buffered tantivy upserts; "a missed commit still self-heals on the next writable open" (`fact_ledger.rs:326-348`, found live 2026-09-15). An eventual-consistency invariant between log and derived index, undocumented outside the code comment.
3. **Poisoned-lock cache invalidation in `ScopedStore`.** After a panic mid-decision the `seen`/`evidence` caches are cleared rather than trusted (`scope.rs:380-392`) — visibility decisions are never served from unknown state.
4. **Stable-partition exact-name promotion.** `promote_exact_name_matches` (`lib.rs:1182` region) promotes exact case-insensitive name matches without re-scoring, preserving relative order — "only promotes, never re-scores" is a stated postcondition with no RFC.
5. **`RelationshipKind` parsing is total.** `FromStr` is `Infallible`; unknown names become `Custom` (`kir/src/lib.rs:163-189`) — query inputs can never crash kind parsing.
6. **`content_signature` is storage-format-independent** (canonical JSON, never compressed bytes; `lib.rs:44-46`) — the invariant that makes cross-backend merge and migration (rows 9–10) sound; stated only in the function's doc.
7. **Per-call and process scopes compose by intersection and a bad scope fails closed** (`read_scope.rs:589`, `:609`; RFC 0181 says "a scope can therefore only remove" but not that a *malformed* scope kills the call rather than being ignored).
