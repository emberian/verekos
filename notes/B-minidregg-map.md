# TASK B — Would EKOS be expressible as a minidregg world? Primitive-to-primitive mapping

**Summary (5 lines).**
1. EKOS's data plane (append-only ledger of Objects/Relationships/Evidence/Events, reviewable unconfirmed merges, read-only Runtime) maps onto minidregg's hyperdocument cell + causal version DAG + reactive views largely *naturally* — 7 of 19 constructs are exact fits, 10 fit with adaptation, 2 have no counterpart.
2. The flagship exact fits: the Runtime is an `ObserverLens` over the canonical cell; unconfirmed-SameAs-until-human-review is `ConflictRecord`'s own discipline ("resolution is a later authority-sensitive operation, not a projection"); evidence provenance is the annotation/revision-anchor apparatus.
3. The forced part is the operational costume: connectors must become SPK grains with principal capabilities, and every pass pays per-declaration admission (authority + laws + read roots + funding) with re-execution — an enterprise batch compiler's economics and its trust-the-connector-redact-early entry model both fight minidregg's defaults.
4. Biggest mismatches: (a) raw-content entry vs typed-declaration admission; (b) EKOS's broadly-readable compiled corpus vs minidregg's sealed-by-default disclosure and encrypted fragments; (c) whole-corpus deterministic passes vs priced per-turn admission, with no `object_at` point-in-time query or domain-time (`valid_from`/`valid_until`) carrier ready-made.
5. An identity-resolution pass written *in* Core4 is blocked today by named gaps (no digest term, no cross-package/dynamic reference, no termination bound, trusted surface semantics); as a Lean effect-family function behind a law it follows the existing `HyperdocumentOperations` pattern almost directly.

## 2. Exact fits: which Lean theorem or structure already carries the property

- **Runtime read-only (row 14).** EKOS enforces this by test/convention. minidregg carries it in the *types*: a lens only projects (`CanonicalReactiveView.lean:41-54`), and the load-bearing theorem is `ObserverLens.project_eq_of_clean` (:98-110; uniform-store twin `Lens.project_eq_of_clean`, ReactiveReceipt.lean:82-91) — a clean receipt provably cannot change the projection, using the receipt's frame law (`ReceiptDelta.frame`, :30-34). The teeth theorem `Example.underDeclared_lens_impossible` (CanonicalReactiveView.lean:382-393) proves a lens cannot under-declare dependencies and still observe a written address — a *property EKOS cannot even state* about its Runtime.
- **Idempotence/exact retry (row 5).** `ValidOperation.preRootExact` + `guardsValid` (HyperdocumentOperations.lean:379,385) make every accepted write conditional on the exact expected prior state; `Accepted.post_contains_guardedSet` (:640-653) proves each guarded write lands in the canonical post. The operational corollary — an uncertain submit is never resubmitted, only looked up by exact ingress — is the documented SPK discipline (SPK-LIFECYCLE.md:92-96), with at-most-once markers (:27-31).
- **Deterministic passes (row 10).** `Store.Patch.ResultAt` + `CellState.ValidatedPatch.resultAt` (AcceptedCellEffect.lean:42-53): the verifier-minted post realizes the declaration's own run, definitionally (`fun _ _ => rfl`). For in-language runs: `sourceStep_deterministic`, `execution_data_unique` (OBJECTIVE-BEND.md:776,784) and `admitted_data_unique` — "two admissions of one term extract the same Data under any capacities" (:710-711).
- **Append-only ledger with authorship (row 4).** `VersionEventRecord.toCausalPreimage` is injective (Hyperdocument.lean:699-715), so distinct events never alias; `StoredVersionEvent.record_eq_of_key_eq` (:831-840) binds equal keys to equal records under the explicit binding premise — minidregg states as a *premise* what a content-addressed ledger assumes silently.
- **Unconfirmed-until-review (row 11).** The `ConflictRecord` docstring (Hyperdocument.lean:473-474) is the theorem-shaped statement: concurrent values remain representable with provenance, and resolution is authority-sensitive, never a projection. Provenance is typed: `author : PrincipalRef`, `operation : OperationId` on every alternative (:466-471).
- **Staleness (row 17).** Revision-anchored pins with `EndpointDeathPolicy` fixing behavior when a neighbor dies (Hyperdocument.lean:383-412); `transclusion_pinned` proves a pin either retains the same authored bytes or reports movement (`protected-authored-fragments.md:55-59`); `classifyCursor` + `Liveness` make "approximately reconstructed" a distinct, non-masquerading constructor (ReactiveReceipt.lean:160-196).
- **Human-only review (row 13, partial).** `AuthenticatedPrincipal` (Hyperdocument.lean:244-267) carries the full lineage/epoch/revocation check as proof fields — EKOS's "human reviewer" is a session flag; here it is a credential path. The *law* half is `Pred` over the request (OBJECTIVE-BEND.md:724-726), enforced by the kernel on every route (:404-413).

## 3. What minidregg forces that EKOS lacks — help or burden

| Forced construct | Help for an enterprise knowledge compiler? | Burden? |
|---|---|---|
| **Principals with capability lineage** (Hyperdocument.lean:197-267; vocabulary `docs/README.md:49`) | Yes — every assertion, edge and review verdict gains a typed, revocable provenance chain; EKOS evidence confidence becomes *who vouches*, not just a number. | Connectors and schedulers must hold credentials and custody; an infra cron job becomes a member. |
| **Funding / priced admission** (`RequestEnvelope.cost`, HyperdocumentOperations.lean:249; domain-judgment pricing, OBJECTIVE-BEND.md:446-453) | Yes, as quota: runaway compiles are refused, not tragic. | Real overhead: every pass and every connector run is metered and paid; an enterprise batch compiler needs an accounting story it does not have today. |
| **Receipts / retained outcomes** (`Accepted.receiptEvent`, HyperdocumentOperations.lean:704-713; `docs/README.md:57`) | Yes — EKOS Evidence gains replayable, exactly-once provenance for free. | Storage and receipt-continuity discipline on every operation. |
| **Admission laws** (Pred; package and domain laws, OBJECTIVE-BEND.md:722-757) | Yes — redaction and deny-wins stop being test conventions and become enforced clauses. | The enforced law fragment is small (no nested paths, fixed ref shapes, :755-757): a PII-regex redaction law *will not fit* and must live in the Lean family/admission code instead — i.e., exactly where EKOS keeps it today. |
| **Encryption of fragments** (AuthoredFragment, Hyperdocument.lean:271-292; sealed atoms/annotations, `protected-authored-fragments.md:7-25,43-53`) | For regulated PII, yes: per-fragment 256-bit content keys, immutable ciphertext, rewrappable custody, and the honest law "revocation cannot erase already disclosed plaintext" (:39-41). | For EKOS's *product* it is the wrong default: a compiled knowledge graph exists to be queried by everyone in scope; sealed-by-default disclosure (`DisclosureDecision`, AcceptedCellEffect.lean:68-75) means the Runtime cannot read its own corpus unless everything is published unsealed — at which point the machinery is dead weight. |

Net: principals, receipts and laws help an enterprise compiler (they are what EKOS approximates with conventions); funding and fragment encryption are genuine burdens unless the deployment actually wants metering and ciphertext custody.

## 4. Judgment: natural world or forced one?

**A natural world wearing a forced operational costume.** The ledger-as-hyperdocuments, evidence-as-anchored-annotations, disputes-as-conflicts-and-links, and Runtime-as-reactive-view mappings are natural — several (rows 2, 4, 11, 14, 17) are exact, and row 14 is *stronger* in minidregg than in EKOS. The forcing appears when you insist on the brief's specific embodiment: connectors as SPK grains, passes as admitted computations.

The three biggest mismatches, concretely:

1. **Entry trust model.** EKOS: the connector is the trusted raw-content entry point, with a redaction law applied *there* because raw text never gets another chance to be kept out. minidregg: no raw content is ever admitted — `Action` is six structured verbs (HyperdocumentOperations.lean:80-86), every declaration comes from an authenticated principal, and admission re-checks authority, laws, read roots and funding (docs/README.md:33). A connector therefore must be a principal + grain whose *internal* parsing is invisible to admission: redaction moves from an enforced law at a named chokepoint to an unverifiable activity inside a sandbox. That is a real regression for EKOS's central privacy guarantee (see row 9: no counterpart).
2. **Readability of the compiled corpus.** EKOS's Runtime is read-only *and broadly read*; deny-wins scopes narrow it at the edges. minidregg's disclosure defaults run the other way: sealed-by-default `DisclosureDecision` (AcceptedCellEffect.lean:68-75), `sealedOnly` disclosure in the hyperdocument family (HyperdocumentOperations.lean:462-465), and encrypted fragments with key custody. An EKOS-on-minidregg must either publish everything unsealed (fighting the machinery) or make its Runtime a keyholder (importing all the custody/recovery complexity of `protected-authored-fragments.md` for no product benefit).
3. **Whole-corpus passes vs per-turn admission.** An EKOS pass deterministically recomputes the derived graph from the whole ledger. minidregg prices and admits per declaration, re-executes at admission and replay (OBJECTIVE-BEND.md:684-696), and has no `object_at`/point-in-time query primitive (row 6) and no domain-time carrier (row 7) — a whole-corpus pass is one enormous funded admitted computation (envelope limits, no digest primitive in Core4, OBJECTIVE-BEND.md:832-833) or a Rust-side batch with no semantic standing. Bitemporal validity (`valid_from`/`valid_until`), which EKOS needs to *state* what a pass consumes, is fields-plus-law here.

## 5. Identity resolution in Objective Bend / Core4 vs a Lean function behind a law

**What Core4 already gives the pass.** A genuinely nice shape: the resolver as an *activity* — it yields typed Plans ("create SameAs edge for X,Y at score s") and waits; human review is the typed Response; confirm/reject is `resume` (`OBJECTIVE-BEND.md:334-339`; perform is never a value, resume only on yielded states, :379-384). Unconfirmed-until-resumed is then *operational*, not a flag. Records, sums, lazy `fix`, and `writeOnce` field laws for confirmed merges all exist.

**What Core4 lacks first (all from "What is open", `/Users/ember/dev/minidregg/docs/OBJECTIVE-BEND.md:810-836`, plus the term table :60-79):**
- **No digest primitive callable from source** (:832-833) — content-signature keys, dedup and idempotence, the heart of identity resolution, cannot be computed in-language.
- **No cross-package or dynamic reference** (:821-822: no surface form names another package's root; no dynamic selection by label; "no generative identity beyond the kernel's object ids") — a resolver must walk *arbitrary* objects generically; Core4 cannot even name them.
- **No termination or resource bound** (:825 no check that a well-typed resident's segment terminates; :826-827 completion is finite, not bounded, and `stepRaw` is linear in the heap) — a pass over an unbounded corpus can exhaust ticks mid-merge.
- **Trusted surface semantics** (:812-817: `.obend` has no meaning of its own; the front end is a named trusted boundary; C4 ancestry invariants are unchecked `Prop`s backed only by vector evidence) — an enterprise correctness argument ("the pass is deterministic and reviewed") would have to be made about the front end's output, not the source.
- **Law fragment too small** (:818-820; :755-757) for threshold logic; confidence must be scaled naturals (no floats in `Term`, :69); no sealing/final/field enumeration (:834); Core4 is not even in the evaluator `registry` (:835-836).

Until those close — digest term, generic object reads, a termination bound, surface-semantics theorems — identity resolution in Core4 would be a reconstruction of the resolver in a language that cannot address the corpus it resolves.

**As a Lean function behind a law, it is nearly free.** The pattern is `HyperdocumentOperations` itself: define the resolver's output as a new first-order action/payload family whose guarded patch is *derived* (no callback supplies a post-state, HyperdocumentOperations.lean:4-8), with `ValidOperation`-style validation at the exact pre-cell (:374-386), determinism definitional via `ResultAt` (AcceptedCellEffect.lean:42-53), and the human-review gate as an enforced `Pred` law over `request.subject` plus a `writeOnce` confirmed-field (OBJECTIVE-BEND.md:724-726,731). The "derived path is the ONLY path" law of this repo (project CLAUDE.md) points the same way: the pass is a compiler arm grown in Lean, with Objective Bend reserved for the connector-side glue and resident tooling. The honest cost of that choice is the one Objective Bend exists to remove: the pass is trusted Lean semantics rather than an admitted, law-checked program — the same trade `AcceptedCellEffect` documents verbatim ("trusted Lean semantics, not a callback ABI", AcceptedCellEffect.lean:124-130).
